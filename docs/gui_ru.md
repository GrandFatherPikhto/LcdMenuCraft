# 🖥️ GUI (PyQt6)

> Тонкая PyQt6-обёртка над тем же конвейером, что использует CLI (`MenuConfig` →
> `MenuValidator` → `MenuFlattener` → `MenuCraft` → `MenuGenerator`): визуальное
> редактирование дерева меню, валидация и генерация C-файлов — без каких-либо
> изменений в [`generate_menu/`](../generate_menu/).

---

## 1. Запуск

```bash
# из корня проекта, с установленными зависимостями (PyQt6 уже в requirements.txt)
python gui.py

# или как модуль
python -m gui
```

Обе точки входа повторяют bootstrap [`generate_menu.py`](../generate_menu.py):
добавляют корень проекта в `sys.path` и меняют рабочую директорию на него, т.к.
значения конфига (`templates_path`, `output_directory`, `flatten`) резолвятся
относительно CWD, а не относительно расположения самого файла конфига.

При запуске GUI открывает файл меню, на который указывает
[`config/config.yaml`](../config/config.yaml) (либо последний открытый файл из
[`gui_settings.json`](#6-настройки), если он всё ещё существует).

## 2. Раскладка

```
┌───────────────────────────────┬─────────────────────────────────┐
│  Дерево меню                  │  Свойства узла                  │
│  Add child / Add sibling /    │  набор полей зависит от         │
│  Delete / Move up / Move down │  type / role узла                │
├────────────────────────────────┴─────────────────────────────────┤
│  Лог (поиск, подсветка по уровню, Copy All)                       │
└────────────────────────────────────────────────────────────────────┘
```

- **Панель дерева** (слева, [`gui/tree_panel.py`](../gui/tree_panel.py)) — живое
  дерево меню, работающее прямо с теми же словарями узлов, что использует
  backend. Структурные изменения мутируют этот вложенный список напрямую, после
  чего дерево полностью перестраивается из него — для размеров дерева в этом
  проекте (десятки узлов) это проще и надёжнее, чем инкрементальная правка
  элементов Qt. Уникальность id новых узлов проверяется по **всему** дереву,
  как это делает `MenuValidator` при поиске дубликатов.
- **Форма узла** (справа, [`gui/node_form.py`](../gui/node_form.py)) —
  перестраивается при каждом выборе узла. Какие поля показываются (`type`,
  `role`, `min`/`max`/`step`, `values`/`default_idx`, `factors`, `controls`,
  `navigate`, шесть опциональных callback-полей) определяется теми же правилами,
  что использует backend, читаемыми напрямую из
  [`config/menu_data.yaml`](../config/menu_data.yaml) через `MenuData`.
  Контролы роли, помеченные как `required: true` (например, `click`/`position`
  у роли `factor`), показываются предвыбранными и заблокированными — это чисто
  информационно: простой просмотр узла ничего в него не записывает. Два поля не
  зависят от роли напрямую: необязательный **Tag** (у любого листа) и
  необязательный список **Raw values**, показываемый только для `role: fixed`,
  параллельно **Values** — см. [`tag`/`raw_values`](./jinja_templates_ru.md#33-конфигурация-узла-menuconfighoutputincludemenuconfigh)
  в справочнике по генерируемому коду. Если список Raw values опустошить,
  ключ удаляется целиком, а не остаётся `[]`.
- **Панель логов** (снизу, [`gui/log_panel.py`](../gui/log_panel.py)) — сюда в
  реальном времени попадают все вызовы `logger.error/info/debug(...)`, которые и
  так уже делают `menucraft.py`/`menu_generator.py`/`menu_flattener.py`/`common.py`,
  поскольку к корневому логгеру подключён один `logging.Handler` — никаких
  изменений в backend для этого не требовалось. Строки подсвечиваются по уровню
  (error/warning/debug), есть поиск (`QTextEdit.find`) и кнопка «Copy All».

## 3. Действия меню / тулбара

| Действие | Эффект |
|----------|--------|
| Open... | Загружает другой YAML-файл меню, заменяя текущий документ |
| Save / Save As... | Сохраняет текущее дерево обратно в YAML (`Ctrl+S` для Save). Что не сохраняется — см. [§5](#5-известные-ограничения) |
| Set output directory... | Записывает значение в `config.output_directory` **внутри самого файла меню** — то же поле, которое читает `generate_menu.py` |
| Validate | Запускает `MenuValidator` по текущему дереву в памяти — сохранение не требуется |
| Generate C files | Повторяет точную последовательность `cli.py` (`MenuCraft` → проверка `validate_required_functions()` → `MenuGenerator`) в фоновом `QThread`, чтобы реальный рендеринг Jinja2 и запись файлов не подвешивали окно |

Закрытие окна с несохранёнными изменениями предлагает Save / Discard / Cancel.

## 4. Как Generate не трогает `config/config.yaml`

`MenuCraft(config_path: str)` и `MenuGenerator(config_path, processor=None)`
принимают только **путь** к конфигу и всегда перезагружают его с диска — нет
публичного способа передать им дерево прямо из памяти. Перезаписывать
собственный `config/config.yaml` репозитория при каждом клике означало бы
неожиданный диff в общем, отслеживаемом git-ом файле при каждом использовании GUI.

Вместо этого [`MenuDocument`](../gui/document.py) ведёт собственный
«тень»-конфиг, `config/.gui_config.yaml` (в `.gitignore`). Он копирует четыре
фиксированных ключа конвейера — `menu_schema`, `data_rules`, `generation_files`,
`flatten` — буквально из настоящего `config/config.yaml`, а свой ключ `menu:`
указывает на **абсолютный** путь к текущему открытому файлу (`MenuConfig`
резолвит этот ключ относительно директории самого тень-конфига, поэтому
относительный путь резолвился бы неверно).

*Generate* всегда: сохраняет открытый документ на диск, обновляет `menu:` в
тень-конфиге, затем выполняет `MenuCraft(shadow_config)` → проверку
`validate_required_functions()` (корректно прерываясь, как и CLI, если
отсутствует обязательный callback) → `MenuGenerator(shadow_config, processor=...)`.
`config/config.yaml` никогда не открывается на запись.

## 5. Известные ограничения

- Сохранение использует `yaml.safe_dump`, поэтому **комментарии и форматирование
  YAML-файла не сохраняются** при записи. Ничего в текущем наборе функций не
  требует сохранения форматирования при round-trip, поэтому это не решалось
  подключением библиотеки типа `ruamel.yaml` — стоит вернуться к этому, если
  станет реальной проблемой.
- Нет сценария «New menu» — GUI всегда открывает существующий YAML-файл (по
  умолчанию тот, что указан в `config/config.yaml`).

## 6. Настройки

Геометрия окна, последний открытый файл меню и последняя output-директория
сохраняются в `gui_settings.json` в корне проекта (в `.gitignore`,
[`gui/settings.py`](../gui/settings.py)). Файл читается терпимо к ошибкам —
отсутствующий или повреждённый файл настроек приводит к использованию значений
по умолчанию, а не к падению приложения.

## 7. Структура исходников

```
gui.py                    # корневая точка входа (повторяет generate_menu.py)
gui/
  __init__.py              # только докстринг + __version__, без реэкспортов
  __main__.py               # обеспечивает `python -m gui`
  app.py                     # bootstrap QApplication, подключение обработчика логов
  document.py                 # MenuDocument -- единственный модуль, импортирующий generate_menu
  main_window.py                # меню/тулбар, раскладка сплиттеров, wiring, обработка закрытия
  tree_panel.py                  # дерево + структурные изменения (add/delete/move)
  node_form.py                    # динамическая форма свойств узла
  log_panel.py                     # панель логов + Qt-обработчик логирования
  settings.py                       # сохранение настроек в JSON
```

Ни один файл внутри [`generate_menu/`](../generate_menu/) GUI не изменяет;
[`tests/`](../tests/)/[`test/`](../test/) и `python -m pytest -q` не затрагиваются.
